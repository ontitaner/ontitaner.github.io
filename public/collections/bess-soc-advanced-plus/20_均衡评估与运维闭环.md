# 20 均衡评估与运维闭环

**一句话**：均衡效果不能只看极差变小；必须在可比工况下证明最低簇能力改善，才能关闭异常事件。

## 20.1 运行场景

20:00，晚峰任务结束。第 19 章已将第 4 簇标记为持续异常，EMS 为次日任务预留夜间低负荷窗口。BMS 可以执行均衡，但值班员不能仅因“均衡已运行”就恢复第 4 簇相关的能力计划。

均衡前后如果温度、静置时间、电流或参数版本不同，极差变化可能来自工况，而不是均衡。次日能否恢复原计划，取决于最低簇可用能量是否在可比条件下真正改善。

## 20.2 决策困难与算法需求

被动均衡把高 SOC 簇的多余电荷泄放为热量，极差缩小但可用能量不增；主动均衡把电荷从高 SOC 簇转移到低 SOC 簇，极差缩小且最低簇能量可能上升。只看极差变小无法区分这两种情况——极差从 5% 降到 2%，但最低簇可能仍在降低（其他簇被拉下来了）。

如果均衡后不经过同工况对比就关闭异常事件，次日晚峰任务可能再次因同一簇提前触限。反过来，如果降温导致极差暂时收缩、均衡实际上没有效果，却要求反复均衡，又会延误备件更换时机。

因此需要三项判断：均衡损耗计算（量化能量得失）、同工况准入（温度、静置时间、电流可比才比较前后）、能力改善评估（最低簇可用能量是否真正提升）。算法输出一个明确结论——关闭事件、继续均衡，还是升级为工单。

| 方式 | 原理 | 代价 |
|---|---|---|
| 被动均衡 | 高 SOC 簇泄放，多余电荷变热 | 耗能、发热 |
| 主动均衡 | 高 SOC 向低 SOC 转移 | 转换损耗、控制更复杂 |

```text
E_cl = C_cell·V_cell·N_s/1000      （每簇名义能量，见附录 A.8）
ΔSOC = I_bal·Δt/(3600·C_cell)     （Δt 单位 s，除 3600 后为 Ah）
E_loss,passive = ΔSOC·E_cl
E_loss,active = ΔSOC·(1−η_bal)·E_cl
ΔE = E_min,after − E_min,before
```

| 变量 | 含义 | 单位 |
|---|---|---|
| `C_cell` | 单体额定容量 | Ah |
| `V_cell` | 单体标称电压 | V |
| `N_s` | 每簇串联单体数，本教程 416 | 串 |
| `I_bal` | 均衡电流 | A |
| `Δt` | 均衡持续时间 | s |
| `η_bal` | 主动均衡转换效率 | 0～1 |
| `E_cl` | 每簇名义能量 | kWh |
| `E_loss` | 均衡损耗能量 | kWh |
| `E_min,before/after` | 均衡前/后最低簇决定的可用能量 | kWh |

`E_loss` 按整簇能量折算，所以 `E_cl` 必须包含 `N_s`（416 串），与第 19 章木桶口径一致；用单体能量会把损耗缩小 416 倍。

BMS 执行均衡与保护，EMS 只预留低负荷窗口、消费能力结果并保存记录。

## 20.3 可比性准入

前后数据均应满足：质量为 `good`、温差≤2°C、电流绝对值≤5 A、静置≥1800 s、BMS 参数版本和 EMS 维护窗口相同。任一条件不满足，结果为“待复测”。

## 20.4 手算示例

每簇能量 `E_cl=314×3.2×416/1000=417.9968 kWh`，`SOC_min=0.05`。

**第 1 步：均衡前能力。**

```text
E_before=4×(0.45−0.05)×417.9968=668.8 kWh
极差=15.0%
```

**第 2 步：复测后能力。** 最低簇 SOC≈0.536：

```text
E_after=4×(0.536−0.05)×417.9968≈812.6 kWh
ΔE=812.6−668.8≈143.8 kWh
```

**第 3 步：单步均衡量与单步损耗。** `I_bal=5 A`、`Δt=1800 s`：

```text
ΔSOC = 5×1800/(3600×314) = 0.007962
单簇被动损耗 = 0.007962×417.9968 = 3.328 kWh
单次主动转换损耗 = 0.007962×(1−0.90)×417.9968 = 0.333 kWh
```

**第 4 步：两种方式的累计损耗与收敛。** 初始 `SOC=[0.60,0.58,0.55,0.45]`，极差阈值 2%：

```text
被动：17 步，42 次簇级泄放 → 损耗 139.776 kWh，末态极差 1.85%
主动：12 步，12 次转移     → 损耗 3.9936 kWh，末态极差 1.22%
```

主动均衡损耗约为被动的 1/35，步数也更少（12 步对 17 步）；代价是转换电路和控制更复杂。被动均衡结构简单，但把电量变成热量。损耗必须按整簇能量 `E_cl` 折算，且只在同工况复测后才能与能力改善一起用于关闭事件。

## 20.5 核心实现

```python
from dataclasses import dataclass


@dataclass(frozen=True)
class EffectReview:
    status: str
    capability_before_kwh: float
    capability_after_kwh: float
    gain_kwh: float


def evaluate_effect(before_soc: list[float], after_soc: list[float],
                    before_temperature_c: float, after_temperature_c: float,
                    current_a: float, rest_s: float,
                    quality: str, same_version: bool) -> EffectReview:
    """按可比性准入，评价均衡前后最低簇能力。"""
    if quality != "good" or abs(before_temperature_c-after_temperature_c) > 2:
        return EffectReview("待复测", 0.0, 0.0, 0.0)
    if abs(current_a) > 5 or rest_s < 1800 or not same_version:
        return EffectReview("待复测", 0.0, 0.0, 0.0)
    energy_per_cluster = 314.0 * 3.2 * 416 / 1000.0
    before = len(before_soc) * max(0.0, min(before_soc)-0.05) * energy_per_cluster
    after = len(after_soc) * max(0.0, min(after_soc)-0.05) * energy_per_cluster
    status = "可关闭" if max(after_soc)-min(after_soc) < max(before_soc)-min(before_soc) and after > before else "继续处置"
    return EffectReview(status, before, after, after-before)


if __name__ == "__main__":
    review = evaluate_effect([.60,.58,.55,.45], [.54,.54,.536,.536], 25.0, 25.5, 0.0, 1800, "good", True)
    print(review)
    assert review.status == "可关闭" and review.gain_kwh > 0
```

## 20.6 运维闭环

```text
告警 → BMS 处置 → 同工况复测 → EMS 关闭或继续处置
```

```mermaid
flowchart LR
    EVENT["GA-002-C4\n簇4连续异常"] --> WINDOW["EMS 预留夜间\n低负荷窗口"]
    WINDOW --> BMS["BMS 执行均衡\n记录温度和参数版本"]
    BMS --> RETEST["同工况复测\n质量、静置、温度、电流"]
    RETEST --> JUDGE{"极差下降且\n最低簇能力提升？"}
    JUDGE -- "是" --> CLOSE["关闭事件\n恢复经批准能力"]
    JUDGE -- "否" --> KEEP["继续处置\n复测或升级工单"]
```

关闭条件：工况可比、均衡收敛、极差降低、最低簇能力改善。否则保留事件，安排复测或升级工单。
