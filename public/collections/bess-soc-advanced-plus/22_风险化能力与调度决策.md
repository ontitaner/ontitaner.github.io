# 22 风险化能力与调度决策

**一句话**：调度不应只收到"最大功率"，还应收到风险口径、限制原因和明确动作；诊断状态必须转换成降额、重规划或停止发布。

## 22.1 运行场景

17:45，在线诊断已将状态标记为 degraded：连续残差异常使估计余量从 3% 扩大到 4.5%。第 21 章在 normal 口径下给出 1288.9 kW 的 30 min SOP，但值班员必须决定 degraded 状态下是否仍能按此功率申报，还是需要提前下调计划。

调度不只关心"最大能放多少"，还关心该功率在当前状态下有多大把握、限制来自哪里、系统是否已经进入需要人工复核的状态。

## 22.2 决策困难与算法需求

SOP 只是在给定状态和余量下的功率结果；它没有规定当诊断状态恶化时该使用哪一个余量。若继续发布 normal 数值，会把已知的估计风险带入任务；若完全停止所有任务，又无法区分可保守执行和数据完全不可用。

**如果做错会怎样**：按 1288.9 kW 发布 30 min 任务，但 degraded 状态下真实 SOC 可能比点值低 4.5 个百分点——任务执行到第 20 分钟，最低簇触限，PCS 被迫降功率，调度侧收到一次非计划降额。如果反过来一律停止发布，则白白放弃了 1160 kW 的可执行功率。

因此需要一套口径来量化"多大把握"：将第 18 章的 `k_risk=1.96`（约 95% 单侧覆盖）按诊断状态选择性地放大，使 normal 时照常发布，degraded 时自动降额，invalid 时停止发布。这就是风险化能力策略——不是换公式，而是按状态选余量。

## 22.3 能力口径与设计思路

**为什么选 P50/P90/P99？** 这些是工业界约定的统计分位口径，不是随意起名：P50 是正常能力的中间估计，P90 在正常状态下的 `k_risk=1.96` 恰好对应约 95% 单侧覆盖（`k_risk·σ_SOC`），degraded 时 `k_state=1.5` 将余量放大，把同一套统计框架映射到不同风险姿态。

- **P50**：通常可达到的能力。
- **P90**：九成把握可达到的能力（normal 时即 `k_risk=1.96` 口径）。
- **P99**：保守安全边界。

风险口径不是滤波器参数，而是业务选择。能力结果应同时写明对象、方向、持续时间、测量平面、SOH/效率版本、质量状态、风险余量和瓶颈。

## 22.4 状态与动作

| 诊断状态 | 余量处理 | EMS 动作 |
|---|---|---|
| `normal` | 使用已记录的 `m_est` | 发布 SOE/SOP 与瓶颈 |
| `degraded` | `m_est` 乘 1.5 后重算 | 降额、重规划、记录原因 |
| `invalid` | 不计算新能力 | 不下发新计划，等待新鲜数据 |

## 22.5 风险化能力公式

风险化不是换一个滤波器参数，而是在第 20–21 章的 SOE/SOP 公式上做一次状态相关的余量放大：

```text
m_est' = k_state × m_est
SOC_low = max(0, SOC − m_est' − ΔSOC_cluster)
SOE' = max(0, SOC_low − SOC_min) × E_eff × η_DC→AC
P_energy(T) = SOE' / (T/3600)
SOP' = min(P_energy(T), P_BMS, P_PCS, P_grid)
```

| 变量 | 含义 | 单位 |
|---|---|---|
| `k_state` | 诊断状态系数：`normal`=1.0、`degraded`=1.5、`invalid` 不计算 | 无量纲 |
| `m_est` | 正常口径估计余量，来自第 18 章 `k_risk·σ_SOC` 风险口径 | SOC |
| `m_est'` | 风险化后余量，只放大不放小 | SOC |
| `ΔSOC_cluster` | 最低簇相对站级估计的保守差值，来自第 23 章 | SOC |
| `E_eff` | `C_site × SOH_capacity`，见第 20 章 | kWh |
| `η_DC→AC` | 直流到交流效率，只乘一次 | 0～1 |

关键约束：`k_state` 只作用于 `m_est`，不作用于设备限值 `P_BMS/P_PCS/P_grid`；`invalid` 时公式不执行，直接停止发布。

## 22.6 手算示例

第 21 章 `normal` 下：`SOE=644.4 kWh`、`SOP=1288.9 kW`。降级时按〔式 22.5〕有 `k_state=1.5`，`m_est` 从 3% 放大到 `m_est'=1.5×3%=4.5%`。

**第 1 步：收窄可用能量。**

```text
SOC_low = max(0, 30% − 4.5% − 2%) = 23.5%
SOE' = (23.5%−10%)×4614.68×0.931 = 580.0 kWh
```

**第 2 步：重算持续功率。**

```text
P_energy(30min) = 580.0/0.5 = 1160.0 kW
SOP' = min(1160.0, 2200, 2500, 2000) = 1160.0 kW
```

诊断降级使可承诺功率从 1288.9 kW 降至 1160.0 kW。

## 22.7 核心实现

```python
from typing import Optional


def publishable_power(normal_sop_kw: float, degraded_sop_kw: float,
                      diagnostic_state: str) -> tuple[Optional[float], str]:
    """按诊断状态选择可发布功率和 EMS 动作。"""
    if diagnostic_state == "normal":
        return normal_sop_kw, "发布能力"
    if diagnostic_state == "degraded":
        return degraded_sop_kw, "降额并重规划"
    if diagnostic_state == "invalid":
        return None, "停止发布，等待新鲜数据"
    raise ValueError("未知诊断状态")


if __name__ == "__main__":
    power, action = publishable_power(1288.9, 1160.0, "degraded")
    print(f"可发布={power:.1f} kW，动作={action}")
    assert power == 1160.0 and action == "降额并重规划"
```
