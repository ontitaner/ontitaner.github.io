# 04 时序对齐与质量门控

## 4.1 运行场景

16:30，距离晚峰任务还有 90 分钟。EMS 从 BMS 收到一组电压、电流和温度数据，用于更新 RC 模型参数和 SOC。数据看起来都在合理范围：单体电压从 3.300 V 降到 3.250 V，电流记录从 0 A 变为 50 A，温度保持 25°C。

但采集服务发生网络重试，电压样本到达较早，下一拍 100 A 电流样本先被拼接到这一拍电压。屏幕上的数值没有 NaN、没有超量程，值班员也看不到明显告警；如果直接送入参数辨识，欧姆内阻会被估成一半，后续电压预测、SOC 校正和晚峰能力都会产生系统偏差。

## 4.2 决策困难

此时 EMS 不是简单判断“数据有没有”，而是判断“这些数据能否共同代表同一个物理时刻”。如果 16:30 的状态更新已被错拍污染，17:30 的 SOE/SOP 重算会建立在错误状态上。若保守地把所有迟到数据都丢弃，又可能失去恢复任务能力所需的有效信息。

因此需要一个明确的数据契约：确定时间基准、同窗规则、质量等级和异常动作。它让系统能区分正常样本、可降级样本和不可用样本。以下先定义这套契约的要素，再说明如何使用它们。

## 4.3 时间语义

| 时间 | 用途 | 业务含义 |
|---|---|---|
| 设备时间 `device_time` | 追溯设备采样时刻 | 判断原始样本顺序 |
| 接收时间 `receive_time` | 审计到达时刻 | 判断传输延迟和重试 |
| 单调时间 `monotonic_time` | 排序和计算 `dt` | 保证模型按真实间隔推进 |

```text
dt[k] = monotonic_time[k+1] − monotonic_time[k]
transport_delay = receive_time − device_time
```

单调时间只在同一采集会话内比较。设备时间和接收时间保留用于审计，而不是直接替代状态递推的 `dt`。

## 4.4 同窗规则

```text
y[k]   = h(x[k],u[k],θ[k]) + v[k]
x[k+1] = f(x[k],u[k],dt[k],θ[k]) + w[k]
```

- `x[k]`：当前状态；
- `u[k]`：区间 `[t[k],t[k+1])` 的平均电流；
- `y[k]`：与 `u[k]` 同窗解释的电压；
- `x[k+1]`：用 `u[k]` 和实际 `dt[k]` 推进后的状态。

先解释当前量测，再推进下一状态。将 `y[k]` 配给 `u[k+1]` 会改变物理意义。

## 4.5 算法需求

质量门控必须检查有效性、范围、顺序、完整性、时效和冻结状态，并输出三类结果：

| 状态 | 典型证据 | EMS 动作 |
|---|---|---|
| `good` | 同窗、范围正常、顺序连续 | 正常更新状态与能力 |
| `suspect` | 迟到、跳号、冻结 | 记录原因，按策略降级更新 |
| `invalid` | NaN、越界、回退、无法同窗 | 拒绝本拍，等待有效数据 |

这不是为了“过滤坏数据”而已，而是决定 17:30 的能力计算能否使用当前状态。

## 4.6 手算示例

阶跃前：`I[0]=0 A,V[0]=3.300 V`；当前拍：`I[1]=50 A,V[1]=3.250 V`；下一拍：`I[2]=100 A`。

**第 1 步：正确同窗。**

```text
ΔV = 3.250−3.300 = −0.050 V
ΔI = 50−0 = 50 A
r0 = −ΔV/ΔI = 1.00 mΩ
```

**第 2 步：错误拼接。**

```text
ΔV 仍为 −0.050 V
ΔI 被错误配为 100 A
r0_wrong = 0.50 mΩ
```

一次错拍使内阻低估 50%。这会使模型预测电压偏高，EKF 可能把残差错归因于 SOC，最终高估晚峰能力。

## 4.7 核心实现

```python
import math
from typing import Optional


def classify_sample(sample: dict, previous: Optional[dict], config: dict) -> tuple[str, list[str]]:
    """根据有效性、范围、顺序、完整性和时效返回质量状态。"""
    values = (sample["device_t"], sample["recv_t"], sample["mono_t"],
              sample["current_a"], sample["voltage_v"], sample["temp_c"])
    if not all(math.isfinite(value) for value in values):
        return "invalid", ["non_finite"]
    if not config["i_min"] <= sample["current_a"] <= config["i_max"]:
        return "invalid", ["current_out_of_range"]
    if not config["v_min"] <= sample["voltage_v"] <= config["v_max"]:
        return "invalid", ["voltage_out_of_range"]

    reasons = []
    if previous is not None:
        if sample["seq"] <= previous["seq"] or sample["device_t"] <= previous["device_t"]:
            return "invalid", ["duplicate_or_late_device_sample"]
        if sample["mono_t"] <= previous["mono_t"]:
            return "invalid", ["non_monotonic_local_time"]
        if sample["seq"] > previous["seq"] + 1:
            reasons.append("missing_sequence")
        if sample["mono_t"] - previous["mono_t"] > config["period"] * config["gap_factor"]:
            reasons.append("missing_interval")
    delay = sample["recv_t"] - sample["device_t"]
    if delay < 0 or delay > config["max_delay"]:
        reasons.append("late_or_clock_mismatch")
    return ("suspect", reasons) if reasons else ("good", [])
```

完整的会话状态、冻结检测和同窗对齐实现见 `lab/soc_core.py`。
