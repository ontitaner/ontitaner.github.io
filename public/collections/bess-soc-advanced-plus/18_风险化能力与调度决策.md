# 18 风险化能力与调度决策

**一句话**：调度不应只收到“最大功率”，还应收到风险口径、限制原因和明确动作；诊断状态必须转换成降额、重规划或停止发布。

## 18.1 运行场景

17:45，在线诊断已将状态标记为 degraded：连续残差异常使估计余量从 3% 扩大到 4.5%。第 17 章在 normal 口径下给出 1288.8 kW 的 30 min SOP，但值班员必须决定 degraded 状态下是否仍能按此功率申报，还是需要提前下调计划。

调度不只关心“最大能放多少”，还关心该功率在当前状态下有多大把握、限制来自哪里、系统是否已经进入需要人工复核的状态。

## 18.2 决策困难与算法需求

SOP 只是在给定状态和余量下的功率结果；它没有规定当诊断状态恶化时该使用哪一个余量。若继续发布 normal 数值，会把已知的估计风险带入任务；若完全停止所有任务，又无法区分可保守执行和数据完全不可用。

因此需要风险化能力策略：将 normal、degraded、invalid 映射为不同的能力口径和 EMS 动作，使诊断结果自然转成发布、降额或停止发布的业务决定。

## 18.3 能力口径

- **P50**：通常可达到的能力。
- **P90**：九成把握可达到的能力。
- **P99**：保守安全边界。

风险口径不是滤波器参数，而是业务选择。能力结果应同时写明对象、方向、持续时间、测量平面、SOH/效率版本、质量状态、风险余量和瓶颈。

## 18.3 状态与动作

| 诊断状态 | 余量处理 | EMS 动作 |
|---|---|---|
| `normal` | 使用已记录的 `m_est` | 发布 SOE/SOP 与瓶颈 |
| `degraded` | `m_est` 乘 1.5 后重算 | 降额、重规划、记录原因 |
| `invalid` | 不计算新能力 | 不下发新计划，等待新鲜数据 |

## 18.4 手算示例

第 17 章 `normal` 下：`SOE=644.4 kWh`、`SOP=1288.8 kW`。降级时 `m_est` 从 3% 放大到 4.5%。

**第 1 步：收窄可用能量。**

```text
SOC_low = 30% − 4.5% − 2% = 23.5%
SOE_degraded = (23.5%−10%)×4614.68×0.931 = 580.0 kWh
```

**第 2 步：重算持续功率。**

```text
P_energy(30min) = 580.0/0.5 = 1160.0 kW
SOP_degraded = min(1160.0,2200,2500,2000) = 1160.0 kW
```

诊断降级使可承诺功率从 1288.8 kW 降至 1160.0 kW。

## 18.5 核心实现

```python
from typing import Optional


def publishable_power(normal_sop_kw: float, degraded_sop_kw: float,
                      diagnostic_state: str) -> tuple[Optional[float], str]:
    """按诊断状态选择可发布功率和 EMS 动作。"""
    if diagnostic_state == "normal":
        return normal_sop_kw, "发布能力"
    if diagnostic_state == "degraded":
        return degraded_sop_kw, "降额并重规划"
    if diagnostic_state == "invalid":
        return None, "停止发布，等待新鲜数据"
    raise ValueError("未知诊断状态")


if __name__ == "__main__":
    power, action = publishable_power(1288.8, 1160.0, "degraded")
    print(f"可发布={power:.1f} kW，动作={action}")
    assert power == 1160.0 and action == "降额并重规划"
```
