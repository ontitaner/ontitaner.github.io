## 一、先把 Claude Code 接进来

官网的文档是显示可以直接走 Claude Code 接入。

链路是这样的:

```
Claude Code -> CC Switch -> Agnes API
```

准备好这三样：Agnes API Key、CC Switch、Claude Code。

Agnes 的 API 地址是 `https://apihub.agnes-ai.com/v1`，文本模型名是 `agnes-2.0-flash`。

### 第一步：获取 Agnes API Key

先访问 Agnes API Platform：`https://platform.agnes-ai.com/`

注册登录后，进入 API Key 页面，创建并复制一个新的 Key。

![](/images/wechat/2026-06-19-7a3e95/img-1781863723921-mafmk9.jpg)

### 第二步：安装 CC Switch

CC Switch 地址：`https://github.com/farion1231/cc-switch/releases`

安装完成后打开 CC Switch，顶部选择 claude-cli。

![](/images/wechat/2026-06-19-7a3e95/img-1781863723965-nqvsgr.jpg)

### 第三步：开启 CC Switch 路由

![](/images/wechat/2026-06-19-7a3e95/img-1781863724007-osetus.jpg)

先点击CC Switch 左上角设置页，进入路由配置，选本地路由，找到 Claude 相关路由并启用。

开启后，Claude Code 的请求会先走 CC Switch，再由 CC Switch 转到 Agnes API。

### 第四步：添加 Agnes 供应商

回到 CC Switch的Claude 页面，点击右上角加号，新增一个供应商。

供应商类型选 claude，配置方式选自定义配置，主要填这四项:

*   API Key:粘贴刚才创建的 Key
    
*   请求地址:`https://apihub.agnes-ai.com/v1`
    
*   API 格式:openai chat completions
    
*   模型:`agnes-2.0-flash`
    

![](/images/wechat/2026-06-19-7a3e95/img-1781863724052-idy36n.jpg)

### 第五步:获取模型列表

![](/images/wechat/2026-06-19-7a3e95/img-1781863724093-gkakg.jpg)

填完以后，先点一次获取模型列表。

能拉到列表就选 `agnes-2.0-flash`，再按 CC Switch 的提示做模型映射。

这一步跑通，至少说明 Key 和接口地址没问题。

### 第六步：加兼容参数

Claude Code 真实跑起来时，可能会带一些模型不认识的参数，比如 thinking、context\_management 这类字段。

为了避免请求因为参数不兼容直接失败，我在 CC Switch 里加了这段:

```
{  "allowed_openai_params": [    "thinking"，    "context_management"  ]，  "litellm_settings": {    "drop_params": true  }}
```

![](/images/wechat/2026-06-19-7a3e95/img-1781863724138-bt5ago.jpg)

### 第七步：在 Claude Code 里验证

打开 Claude Code，问句：「你好」，能正常回复，基础链路就算通了。

这里界面上虽然还显示 Opus 4.8，但底层已经走到了 `agnes-2.0-flash`。

![](/images/wechat/2026-06-19-7a3e95/img-1781863724181-ovorn.jpg)

## 二、文本模型

我打算做两个跨度差异比较大的任务：一个看它能不能读项目代码，另一个看它能不能从零写一个能跑的网页。

### 源码解析

第一个任务我拿了 [MewCode Agent 项目的源码](https://mp.weixin.qq.com/s?__biz=MzUxODAzNDg4NQ==&mid=2247558479&idx=2&sn=a6c54370626fb417d35df7e257d79819&scene=21#wechat_redirect)，丢给`agnes-2.0-flash`模型来解析，主要看它扫文件、抓主线、归纳模块的能力。

提示词大概是这样：

```
请帮我看看这个 MewCode 项目的整体结构，重点产出两份文档：1. 项目结构概览：列出主要目录、各目录的职责、入口文件;2. 核心模块说明：挑出 3 个最关键的模块，讲清楚每个模块的职责、对外暴露的接口、跟其他模块的调用关系。要求：- 不要罗列所有文件，只挑承担主要业务逻辑的- 模块说明要带上具体的文件路径，方便我回去定位- 如果碰到 TODO、FIXME 或者明显的临时实现，单独列一节标出来
```

它启动了sub agent 去扫源码，然后按目录拆出主线，最后两份文档都出来了。

![](/images/wechat/2026-06-19-7a3e95/img-1781863724225-mf3k7.jpg)

模型先派出 sub agent 把目录扫一遍，再按业务主线分块归纳。整个过程跑下来不到几分钟，两份 Markdown 文档就落到磁盘上，一份讲整体结构，一份挑核心模块逐个剖开，连 TODO 和 FIXME 都单独拎出一节标出来。

模块说明里有给文件路径，模块之间的调用关系明确

![](/images/wechat/2026-06-19-7a3e95/img-1781863724266-yry7gr.jpg)

翻到模块说明这部分，每个模块旁都老老实实标了文件路径，点过去能直接跳到源码。

调用关系也写得清楚，谁依赖谁、谁被谁调，一眼能扫出来。

### 做一个世界杯论坛网页

第二个任务换成纯生成。这种跟代码解析正好相反，前一种考阅读理解，这一种考从零写出能跑的产物。

我让它做一个世界杯论坛页面：

```
请帮我用纯前端做一个世界杯论坛的单页 demo，文件名 worldcup-forum.html。页面要求：1. 顶部导航，左边是站点 logo，右边是登录/注册按钮(纯样式，不用真实跳转);2. 主体分两栏，左侧是帖子列表，右侧是当日赛程卡片;3. 帖子列表至少 5 条，每条带头像、用户名、标题、发布时间、回复数;4. 赛程卡片显示对阵双方、比分、开始时间，至少 3 场;5. 全部静态写在 HTML 里，不要外部依赖，样式用 CSS 写在 <style> 标签里;6. 配色用世界杯主题，绿色为主，辅以暖色点缀。要求：- 只生成一个 HTML 文件，打开能直接跑- 末尾留一个简单的注释说明哪些地方建议接后端
```

![](/images/wechat/2026-06-19-7a3e95/img-1781863724470-b5qxm.jpg)

打开生成的 HTML 一看，顶部导航、左侧帖子列表、右侧赛程卡片，几样要求都老实落地。

配色用世界杯主题的绿，细节也没偷懒：头像、用户名、回复数全了，赛程上对阵和比分都安排上。

估计看到这，有同学会好奇 Agnes 文本模型的上下文长度支持多少呢？

目前是支持 256K，但是我看到官方说，本周灰度上线，即将升级到 1M 上下文，等升级之后，Agnes 文本模型就可以更好地接手大代码仓库的项目了，不用担心模型上下文被挤爆了。

## 三、图片模型

文本之后试图片。Agnes 的图片模型有个我挺看重的特点：能直接出架构图、流程图，而不只是好看的插画。

> 官方生图模型 API 教程：https://agnes-ai.com/doc/agnes-image-21-flash

我没去平台界面点按钮，直接让 Claude Code 按文档把图片生成能力封装成一个 Skill，后面任何工作流里都能调：

```
我想使用 Agnes 的图片生成 API。请访问文档 https://agnes-ai.com/doc/overview，帮我创建一份 Skill，封装图片生成能力。
```

Skill 封好以后，我挑了几个差异比较大的场景。

### 架构图、流程图：程序员写文档的日常痛点

程序员写文档的高频痛点是，架构图、流程图懒得画又不能不画。我先试架构图。

提示词大概是这样：

```
请生成一张清晰的微服务架构图，横版 16：9。要求：- 顶部是用户和移动 App 入口- 中间是 API Gateway，下面分出三个核心服务：用户服务、订单服务、库存服务- 下方是 MySQL、Redis、Kafka 三类基础设施- 每个组件用圆角矩形，标注英文服务名- 连线带箭头，主路径用粗线，异步路径用虚线- 整体配色干净，蓝灰为主，不要花哨不要文字水印，不要装饰图形。
```

![](/images/wechat/2026-06-19-7a3e95/img-1781863724553-4nq618.jpg)

横版铺开一看，顶部用户和 App 入口，中间 API Gateway 把流量分发到用户、订单、库存三个服务，下面挂着 MySQL、Redis、Kafka 三类基础设施。

粗线走主路径、虚线走异步路径，蓝灰圆角矩形配上带箭头的连线，整张图直接搬到技术评审 PPT 上都不用再修。

## 四、视频模型

视频这块我准备了三组，分别测不同能力。

### 漫剧短视频：龙舟比赛

第一组测漫剧风格的真实场景。漫剧短视频在小红书、抖音上是个很大的赛道，要求人物面部、动作、镜头都得稳。

```
漫剧风格短视频，15 秒。场景：端午节的江面，十几条龙舟同时冲出起点，鼓手在船头敲鼓，桨手们整齐挥桨，水花飞溅。起点鸣枪，龙舟从静止冲出，远景拍全部船只;切到中景，鼓手敲鼓的特写、桨手吼号子的口型;切到第一条龙舟冲过终点线的瞬间，船员高举船桨庆祝。镜头有适度晃动，水面反光真实，日光斜射，色调偏暖。不要文字，不要水印。
```

这段 15 秒的漫剧风，节奏抓得比想象中稳。

鸣枪那一下，十几条龙舟齐冲出去，水花溅起来都带光；切到中景，鼓手敲鼓的特写、桨手吼号子的口型都对上节拍；最后第一条船过线，船员高举船桨庆祝。

镜头有点轻微晃动，反而像端午那天在岸边架着手机拍的。

最关键是，这一整套都没花钱。视频模型是最烧钱的赛道，现在能跑两百个候选都没什么心理负担。

### 动画视频：卡通小狐狸学编程

第二组换成卡通动画，看模型对二维风格的把握。

```
卡通动画风格，10 秒。画面里一只橙色小狐狸坐在森林里的树桩上，面前是一台笔记本电脑，旁边放着一杯热可可。狐狸盯着屏幕思考，挠头，有个小灯泡图标在头顶闪了一下;狐狸快速敲键盘，屏幕上出现绿色代码，周围的松鼠和兔子探头围观;屏幕弹出绿色对勾，狐狸高举手臂庆祝，小动物们鼓掌。皮克斯/吉卜力风格，色调温暖，光线柔和，不要文字，不要水印。
```

这段故意挑了个难场景压它：主角狐狸，加松鼠、兔子两个配角，还得有连贯剧情。

结果意外地稳。狐狸从挠头、敲键盘到举手庆祝，动作衔接自然，没出现「换个动作就换张脸」；多角色同框形象也没垮。提示词里的绿色代码、对勾都对上了，树桩旁那杯热可可的暖光，还是它自己补的。

免费模型能把多角色、连贯叙事、氛围细节一起兜住，超出预期了。

  

## 最后

我自己用了几天 Agnes 模型，感受是这样的：论能力，它肯定比不上 Claude Opus，但 Opus 是真的贵，也是真的烧 token。

而 Agnes 完全免费，文本、图片、视频三个模型都不要钱。你随便怎么烧，一分钱都不会花，这就很香了～

更关键的是，Claude Code + Agnes 的效果其实还挺能打的。

所以完全可以这么玩：用 Claude Opus 做任务规划，具体的执行流程丢给 Agnes 去跑。Claude Code 照样爽，再也不用为「今天又烧了多少 token」发愁了。

但要真拿它扛重活，我反而会收着点。像直接改核心代码、成批量出生产素材这种，我不会一上来就梭哈，先切一小块出来试试水。

免费的东西嘛，多少得迁就它一点脾气：人一多就容易卡，长任务能不能稳住得自己盯着，出图出视频也很难一次到位，多跑几版挑着用是常态。把这点时间成本提前留出来，心态就不会崩。

与其反复纠结「它到底行不行」，不如直接拿活喂给它。免费 API 最大的好处就是试错不花钱，接进工作流也就几分钟的事，跑没跑过，差别可大了。

我一般会随手丢几样活给它试：手头的项目让它摸一遍、配图出个几张、再加一段十来秒的短视频。

一圈下来，它配不配留在你的常用清单里，自己心里大概就清楚了。

对了，Agnes 模型后续还会持续升级的，本周将灰度上线最新模型的能力，比如文本模型的上下文长度将会从 256K 直接升级到 1M，图片模型升级后会新增 4K 输出档位，这就更香了。

最后提醒一句。

Agens 模型不是只能接入 Claude Code，官方写OpenClaw、Codex 等等都是可以接入的，每个接入方式都写的很清楚的操作手册，根据自己的需求去接入就行。
